# Solar Constraint Solver 开发指导文档

## 0. 文档目的

本文档用于指导 AI 编程代理（如 Codex）开发一个基于 Rhino / Grasshopper
的日照约束计算工具。

注意：

-   本文档描述的是目标架构和开发意图。
-   当前文档作者无法读取目标代码库，因此不会假设现有项目结构、文件名称、类结构或代码实现方式。
-   开发前请先检查现有代码库，理解已有模块、命名规范、运行环境和可复用能力。
-   如果已有代码中存在类似功能，应优先重构和复用，而不是重新编写。

------------------------------------------------------------------------

# 1. 项目目标

目标不是开发完整建筑日照设计软件。

目标是开发一个：

> Solar Constraint Solver（日照约束计算引擎）

用于：

根据周边需要保护的日照对象，计算设计体量对其产生的影响，并输出可用于
Grasshopper 后续几何处理的数据。

核心思想：

    Protected Object
            +
    Context Object
            +
    Design Object

            ↓

    Solar Analysis

            ↓

    Constraint Result

            ↓

    Grasshopper Geometry Operation

------------------------------------------------------------------------

# 2. 核心对象模型

系统应围绕三个主要对象设计。

## 2.1 Protected Object（被保护对象）

定义：

需要满足日照要求的对象。

典型案例：

-   住宅窗户采光点
-   外墙采光评价点
-   用户手动建立的日照评价点

注意：

第一阶段不要负责自动识别窗户。

假设：

用户已经通过 Rhino / Grasshopper 建立保护点。

输入形式可以是：

-   Point3d
-   Point List
-   带属性的数据结构

每个保护点可能包含：

-   空间位置
-   编号
-   日照要求
-   其他评价参数

------------------------------------------------------------------------

## 2.2 Design Object（设计对象）

定义：

需要被约束和切削的设计体量。

典型案例：

-   最大设计体量
-   初始方案体量
-   建筑控制体量

输入形式：

-   Brep
-   Mesh

系统不应该直接修改该几何。

推荐：

输出约束结果，由 Grasshopper 原生节点完成：

    Design Volume
            -
    Forbidden Volume

            ↓

    Final Design Volume

------------------------------------------------------------------------

## 2.3 Context Object（影响对象）

定义：

参与遮挡计算，但自身没有日照保护要求的对象。

例如：

-   周边公共建筑
-   已有建筑
-   其他影响太阳路径的体量

输入形式：

-   Brep
-   Mesh

用途：

仅参与：

-   Ray Casting
-   Shadow Blocking

------------------------------------------------------------------------

# 3. Python 计算模块职责

Python Script Component 主要负责计算。

负责：

## 3.1 太阳位置计算

输入：

-   经纬度
-   北向
-   日期
-   时间范围

输出：

-   太阳方向向量
-   时间采样信息

------------------------------------------------------------------------

## 3.2 遮挡分析

核心逻辑：

对于每个 Protected Point：

    Point

    ↓

    Sun Direction

    ↓

    Ray

    ↓

    Context + Design Object

    ↓

    Intersection Test

判断：

该时间点是否获得直射日照。

------------------------------------------------------------------------

## 3.3 日照累计

需要支持参数化：

例如：

-   开始时间
-   结束时间
-   时间步长
-   最小连续日照时间
-   最低累计日照要求

注意：

不要把规范值写死。

------------------------------------------------------------------------

# 4. Python 不负责的内容

以下功能建议交给 Grasshopper 原生节点：

## 4.1 合格判断

不要在 Python 中写：

    if sunlight >= 2:
        pass

原因：

规范要求可能变化。

应该输出：

    Actual Sun Hours

由 GH 控制：

    Actual >= Required

------------------------------------------------------------------------

## 4.2 几何切削

Python 不直接：

-   Boolean Difference
-   修改 Brep
-   生成最终建筑

Python 输出：

-   Forbidden Points
-   Constraint Data
-   Forbidden Volume（如果实现）

Grasshopper负责：

-   Mesh/Brep生成
-   Boolean
-   可视化

# 6. 建议输出接口

建议输出：

## Output 1

Protected Point Results

包含：

-   点位置
-   日照累计时间
-   状态信息

------------------------------------------------------------------------

## Output 2

Violation Data

包含：

-   不满足要求的保护点
-   影响程度

------------------------------------------------------------------------

## Output 3

Constraint Geometry Data

用于后续 Grasshopper：

可能形式：

-   Forbidden Points
-   Forbidden Mesh
-   Forbidden Volume

具体实现根据算法选择。

------------------------------------------------------------------------

## Output 4

Report

包含：

-   计算时间
-   参数记录
-   错误信息
-   统计信息

# 7. 推荐开发策略

不要一次实现全部功能。

建议：

## Phase 1：计算验证

目标：

跑通：

    Protected Points

    +

    Context Buildings

    +

    Design Volume

    ↓

    Sun Hours

验证：

-   太阳计算正确
-   射线正确
-   数据结构正确

------------------------------------------------------------------------

## Phase 2：约束生成

增加：

    Violation Detection

    ↓

    Forbidden Space

------------------------------------------------------------------------

## Phase 3：Grasshopper工作流

完成：

    Forbidden Volume

    +

    Design Volume

    ↓

    Boolean Difference

    ↓

    Final Volume

------------------------------------------------------------------------

# 8. 开发前 AI 必须检查

在修改代码前，请先：

1.  阅读项目目录。
2.  阅读已有 Rhino / Grasshopper 相关代码。
3.  确认：
    -   Rhino版本
    -   Python环境
    -   输入输出方式
    -   已有模块
4.  判断哪些代码可以复用。

不要假设：

-   当前没有代码。
-   当前没有太阳计算模块。
-   当前没有几何处理模块。
